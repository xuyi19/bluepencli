## 追问：`__init__.py` 能否删除（20:40）

用户追问上一轮"保留 8 个 `__init__.py`"的判断。**不靠记忆，在 `C:\Windows\Temp` 副本里真删一遍实测。**

### 实测矩阵

| 场景 | 全删 8 个 | 只删嵌套 6 个（留 app/、tests/） | 保持现状 |
|---|---|---|---|
| `uvicorn app.main:app` / `python -m` 导入 | ✅ 正常 | ✅ 正常 | ✅ 正常 |
| **裸 `pytest` 命令** | ❌ `ModuleNotFoundError: No module named 'app'` | ✅ 正常 | ✅ 正常 |
| 同名目录合并风险 | ⚠️ 存在 | ✅ 无 | ✅ 无 |

### 两个坑的机理（可复用）

1. **裸 pytest 挂掉的机理**：没有 `tests/__init__.py` 时，pytest 的 prepend 导入模式把 `tests/`
   而非 `backend/` 插进 `sys.path` → `from app.main import app` 找不到。
   修法：`pytest.ini` 加 `pythonpath = .`（pytest 7+ 支持）。
   **最阴的地方**：`python -m pytest` 不会暴露（CWD 本身在 `sys.path`），只有裸 `pytest` 才复现。
2. **命名空间包跨路径合并**：无 `__init__.py` 时 `app` 是 namespace package，
   `app.__path__` 会**同时包含 sys.path 上所有同名 `app` 目录**（实测列出 2 个），
   `import app.extra` 能成功导入另一个目录下的文件 —— **不报错，静默串味**。

## 22:17  归档章节号跳号 → 暴露 reload 僵尸进程坑

重新实跑 e2e 归档（确认 docs/practice/ 真的能落地）时发现：归档的 .md 章节号是
一、三、四、六——section() 动态计数器的老 bug 版本。

但当前代码已经是新版本（手工 `render_markdown()` 渲染出来一、二、三、四）。

**根因**：uvicorn `--reload` 模式下的 multiprocessing-fork worker 没被 kill。
看进程树：
- 27780 = 主进程（已 kill）
- 39084 = `multiprocessing.spawn_main(parent_pid=27780, ...)` —— 孤儿 worker，仍占用 8100

`taskkill /F /PID 27780` 报"成功"但只杀了主进程，spawn 出去的 fork worker 仍持有端口。
表象：`netstat -ano` 还显示 8100 LISTENING 27780（Windows 网络栈显示的是 stale PID），
但 `Get-CimInstance Win32_Process` 能看到真正的 39084 是 `--multiprocessing-fork`。
**绑不到端口**这件事本身是这次唯一的真实信号——netstat 那个 stale PID 是误导。

**正确杀法**：
```powershell
Get-CimInstance Win32_Process -Filter "Name='python.exe'" | Select ProcessId,CommandLine
# 找出 --multiprocessing-fork 的 worker PID
taskkill /F /PID <worker_pid>
```

或者干脆别用 reload（开发模式跑 uvicorn 不用 --reload，代码改了手动重启）。

**教训**：看到 netstat LISTEN 但 taskkill 说"没找到进程"时，**别相信 netstat 的 PID**，
直接 CIM 查 `CommandLine`，找 `--multiprocessing-fork` 的 worker 一并杀掉。
这事写进 MEMORY.md。

### 方格纸：三个关键点（全是踩出来的）

**① 格宽不能写死。** 原本写 `--cell: 30px`，而作答区容器实测只有 **728px**，
25 格需要 750px —— 每行只挤得下 24 字，格线全部错位。
改成 `格宽 = 容器实测宽 / 列数`（列数固定 25），配 ResizeObserver 跟随窗口/侧边栏变化。

**② 用 `background-size` 声明格块，别靠 `repeating-linear-gradient` 的色标周期。**
`repeating-linear-gradient(to right, c 0 1px, transparent 1px 29.12px)` 理论上周期是 29.12px，
但实测渲染出来的间距明显偏大。换成
`linear-gradient(...1px, transparent 1px)` + `background-size: var(--cell) var(--cell)`
才变得确定 —— 格宽写多少就是多少。

**③ 别假定「中文 = 1em」。** 标准中文字体确实是 1em（本次 canvas 实测确认），
但字体栈回退时可能不是。代码里保留 canvas 实测 em 比例再反推 font-size，
换个环境也不会崩。

### 验证方法（比看截图可靠，值得复用）

- **折行实测**：填 24/25/26/50/51 个字，量**浏览器实际折行数**。
  「25 字 = 1 行」就是格宽算没算对的判据。
- ⚠️ **不能直接读 `scrollHeight`**：它被 `min-height` 撑着，永远等于最少行数的高度
  （我第一次就量出恒定的「12 行」，白高兴一场）。
  必须先把 `height` 压到 `0`，`clientHeight` 归零后 `scrollHeight` 才是纯内容高度。
- **局部 4 倍放大截图**才能看清格线与字是否重合：`captureScreenshot` 带
  `clip` + `scale: 4`。缩略图上根本数不清 —— 我一开始就被缩略图误导，
  以为格线错位，放大后发现严丝合缝。
- ⚠️ **`clip` 用的是文档坐标**（要加 `scrollY`），不是 `getBoundingClientRect` 的视口坐标。
  用视口坐标会截到旁边的空白区（第一次截出来是纯色块）。

## 第二步：风格换肤（Natural Organic）✅

### 做法：类名保留、定义换掉

`style.css` 里 `.neu` / `.neu-sm` / `.neu-inset` / `.neu-press` **四个类名一个没改**，

于是 161 处调用点全部自动跟随，不用逐个改类名。

新 token 建在 `frontend/tailwind.config.js` 的 `colors.c`（前缀 `c-` 避免与内置 `stone`/`amber` 冲突）。
`borderRadius.organic = 1.5rem`、`soft = 1rem`，配合 `transitionDuration.organic`。

### 脚本化替换（关键效率点）

写 `.tools/retheme.py` 一次性做表格化替换，**顺序敏感**（长表达式必须在短色值之前）：

- 第一轮 498 处：阴影表达式、语义标签色板、功能色、十六进制、**327 处 Tailwind 内置灰**
- 第二轮 20 处：图表色、警示色、`#fff`（用负向前瞻 `#fff(?![0-9a-fA-F])` 避免误伤 `#fffdfb`）
- 第三轮 4 处：`rgba(109,93,252,` / `rgba(224,229,236,` —— **十六进制替换漏掉 rgb() 形式**

**漏网的类别（下次注意）**：JS 对象里的内联样式，如
`boxShadow: '3px 3px 6px #d6d3d1, -3px -3px 6px #ffffff'`（`TeachersView.vue`）。
它不是 CSS 字符串，正则匹配不到，得单独 grep `boxShadow|box-shadow`。

### 老师色标（功能性例外）

原来 5 色里蓝、紫是冷色。换成「扩展大地色相」：深湖蓝 `#3d5a7a` / 苔绿 `#4f7d5e` /
赤陶红 `#9c4a42` / 藕紫 `#7a6a9b` / 赭黄 `#9c6b2f`。
注意 Kiwi 原来是 `#6d5dfc`，**跟主色撞了**，必须给独立色相。

### 顺手摘掉 Arco

全项目只用了 `Message` 和 `Modal` 两个 API，却背上 460KB 的 `arco.css`。
换成自实现 `utils/toast.js` + `components/ToastHost.vue`（约 120 行），
`Modal.warning({onOk})` 改成 `await toast.confirm()` 更好读。

**成果**：CSS **405KB → 24KB**（gzip 52.3KB → 5.9KB，降 89%）；
单文件版 3.4MB → 1.9MB；桌面版 zip 24.0MB → 22.7MB。

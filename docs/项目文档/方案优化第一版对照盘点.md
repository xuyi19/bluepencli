## 一、六大痛点逐条对账

这是这份文档最有价值的部分：**先诊断、再开方**。下面是"半年后的复诊"。

| # | 当时的痛点（2026-09-14） | 现状 | 结论 |
|---|---|---|---|
| 1 | **题库短板**：内置是仿真题不是真题；用户导入需手动录入；没有预解析缓存，每次批改塞完整材料 | 内置 **53 套 239 题**真题（国考 24 + 河北省考 16 公开，私有 13）；材料按题裁剪（实测省 79%） | ✅ **已解决**（用户自助导入除外，见第八部分） |
| 2 | **Token 爆炸**：深度模式加载几万字讲义，单次圆桌涨 10~20 倍，用户不知道要关 | 深度模式仍是独立开关（默认关，带"更慢更贵"提示）；材料裁剪全省；**但无 token 预估显示，用户仍不知道会花多少** | 🟡 **缓解未根治** |
| 3 | **采分点漂移**：老师自找得分点、两次批改会漂、幻觉可能生成材料里没有的点 | 有标准走标准（采分点锚定），无标准裸判；`--check` 校验权重/字段；**但 239 题里只有 1 道有人工精校标准**，且跨次一致性**没测过** | 🟡 **机制在、覆盖没跟上** |
| 4 | **辩论开销不可控**：分差 >15% 就辩论，辩论又一轮 LLM，多人时成倍涨 | ⚠️ **`debate()` 与 `fuse()` 仍然整份重发 `paper`**（代码证据见下） | ❌ **未解决** |
| 5 | **缺少硬规则校验**：字数/重复/格式交给 LLM 判断，会出现"重复反复给分""超字数不扣分" | `utils/grading/rules.js` 纯代码零依赖，扣分封顶 20%、只作旁证、不改写 AI 分；**但只注入辩论与合议，不进老师阅卷 prompt** | 🟡 **做了，但没按文档的位置做** |
| 6 | **大作文档位缺失**：没有固定档级阈值，档位判断波动大 | 合议会给档位（一类/二类…）；**没有文档 14.3 那张"档级阈值表"的硬约束** | ❌ **未做** |

### 痛点 4 的代码证据（未解决）

文档 14.1 明确写过：`debate()` 与 `fuse()` 把**整份 paper（含完整材料 + 考生答案）重发**，这正是"辩论开销不可控"的根因；
改造目标是"只发争议点，输入从 O(材料长度) 降到 O(争议点数)"。

实测当前代码（`frontend/src/agents/orchestrator.js`）：

```js
// 第 152-156 行（辩论）
{ role: 'system', content: `${DEBATE_SYSTEM}\n\n${DEBATE_SCHEMA}` },
{ role: 'user',   content: `${paper}\n\n===== 各位老师的独立评分 =====\n${summaries}${facts}` }

// 第 193-197 行（合议）
{ role: 'system', content: `${FUSION_SYSTEM}\n\n${FUSION_SCHEMA}` },
{ role: 'user',   content: `${paper}\n\n===== 各老师独立批改 =====\n${details}${debateText}${facts}` }
```

**两处都仍是整份 `paper`** —— 文档设计的"只发争议点"改造**没有实施**，
所以验收项「争议点辩论 token 比全量重发节省 ≥70%」不达标。

### 痛点 5 的位置差异

文档 14.2.3 要求 `promptBlock` **前置到每位老师的阅卷 Prompt**，并要求老师"照抄这份事实、不得自行改判"。
实测：`formatRulesForPrompt(hardRules)` 的产物 `facts` **只传给 `debate()` 与 `fuse()`**（第 425、429 行），
老师的阅卷调用（`gradeByTeacher`）拿不到它。

影响：**单个老师独立阅卷时（尤其 solo 模式），硬规则的客观事实对这位老师毫无约束**，
只能等到合议阶段当旁证。文档想要的"关进确定的框架"在这一环漏了。

## 二、验收标准逐条判定（第十三部分）

### 2.1 功能验收（13.1）

| 功能 | 文档验收标准 | 结论 | 依据 |
|---|---|---|---|
| 预解析 | 一道真题能生成结构化标准，含采分点/证据/关键词 | ✅ | `--draft`（启发式）+ `--wizard` 产出 `points[{label, weight, keywords, evidence, note}]` |
| 校准 | 出题人能在 **10 分钟内**完成一道题校准 | 🟡 | 工具就绪（预填 + 草稿 + 写前备份），但**没有实测过耗时**（只录过 1 道样板） |
| 结构化阅卷 | 老师输出 JSON，**含 point-level 判定** | ❌ | 老师输出的是分数/档位/批注/维度，**没有逐采分点的判定**（`points[]` 不存在）。采分点覆盖是**程序**算的，不是老师逐点判的 |
| 硬规则 | 字数/格式/结构检测准确，不消耗 LLM | ✅ | `rules.js` 纯函数零依赖，19 套测试里 `test-rules` 24 项 |
| 争议点辩论 | token 比全量重发**节省 ≥70%** | ❌ | 仍整份重发（见痛点 4） |
| 三档模式 | 用户一键切换，**预估 token 显示** | ❌ | 三档没做；token 预估没有（只有"深度模式"一个开关） |
| 导入工具 | Markdown 文件夹能一键导入 | ❌ | 未做 |
| 训练闭环 | 批改后能推荐下一题，画像基于结构化数据 | ✅ | `test-next-question` 18 项、`test-profile` 20 项 |

### 2.2 成功指标（13.2）

| 指标 | 目标 | 实测 | 结论 |
|---|---|---|---|
| 单题 Token（快速模式） | ≤ 1000 | 未测（无快速模式） | ❌ |
| 单题 Token（常规模式） | ≤ 2500 | **3422**（单人 / 大作文 / glm-4-flash） | ❌ 未达标（大作文场景本来最贵，常规小题无实测数据） |

## 八、毕设 / 求职视角（第十五部分）——这份文档最该认真对的一段

文档 15.1 把交付分成三档：**A 能演示（毕设答辩）→ B 能拿出手（求职）→ C 完整方案**。
实际完成度**已经超过 C**（除了导入工具链与题库管理 UI）。

但 15.4 明确写了"**这三块必须做完，且要能画图讲清楚**"——逐条看：

| 答辩必问 | 文档指向的答案 | 现状 |
|---|---|---|
| 为什么五位老师？ | 1.3 用户角色分工 | ✅ 五位老师各有侧重与权重，讲义原文内置，可讲 |
| 分歧怎么处理？ | **4.4 采分点级分歧 + 纯代码合议** | 🟡 **只做了一半**：分歧检测还是总分得分率级（不是采分点级）；纯代码合议是加权平均（不是文档设想的"纯代码裁决"） |
| 怎么保证可重复？ | **4.1 预解析 + 校准 + 结果冻结** | 🟡 **三件里只有"预解析"做齐**：校准 1 道、**结果冻结未做** |

> **这三块里，"分歧处理"和"可重复"是答辩最容易追问的两处，而它们恰好是没做完的两处。**
> 不是代码量的问题——`detectDispute` 升级到采分点级、记录里补 4 个版本字段，
> 都是小改动；**真正的工作量在"校准 40 道"**（只有你能做）。

### 文档 15.2「时间不够时的砍法」与实际做法正好相反

| 文档砍法顺序（从后往前砍） | 实际 |
|---|---|
| ① 砍考场模式 | **做了，还做成了独立入口** |
| ② 砍能力画像 | **做了**（六维雷达） |
| ③ 砍省考导入工具链 | **没做** ✅（与文档一致） |
| ④ 砍题库管理 UI | **没做** ✅ |
| ⚠️ 至少保留：标准 + 硬规则 + 结构化阅卷 + 争议点辩论 | 标准 🟡、硬规则 ✅、结构化 🟡（无 point-level）、争议点辩论 ❌ |

**这个"反向偏差"有解释**：考场模式与能力画像是"纯代码活、不依赖专业判断"，所以我能推进；
而争议点辩论重构、采分点级分歧、40 道校准，要么需要动评分内核的验证（要有校准基础才敢改），
要么需要你本人的判断。**结果就是"好做的先做了，核心的留到最后"**——这正是文档 15.3
那句"数据结构优先、外围功能最后"想防的事。

## 九、结论与建议

**做到的**：这份文档的整条主线"把不确定的 LLM 关进确定的框架"——标准层锚定、硬规则纯代码兜底、
分层展示、训练闭环——都落地了，而且**题库与流水线的完成度远超文档预期**（文档要 9 套国考，实际 53 套）。
测试覆盖（19 套 / 260+ 条断言）也是文档之外多做的，那正是面试官会看的东西。

**没做到的，且都在文档的"必须"清单里**：
1. **争议点辩论文案改造**（仍整份重发 → token 没省下来）——文档点名为痛点 4 的根因
2. **采分点级分歧检测**（仍是总分得分率级）——答辩问"分歧怎么处理"时会被追问
3. **结果冻结**（记录不存标准/prompt/模型版本）——答辩问"怎么保证可重复"时会被追问
4. **硬规则没进老师 prompt**（只在辩论/合议当旁证）——"关进确定的框架"漏了一环
5. 大作文档级、Token 预算制与自动降级、用户侧导入工具链、题库管理 UI、混淆与仓库分离、软著

**如果只做三件事**（按"对毕设/求职的加分 ÷ 工作量"排）：
1. **结果冻结 + 采分点级分歧检测**（都是小改动，但正好补上答辩必问的两块）
2. **硬规则前置进老师 prompt**（一个参数传递的事，让"确定框架"这个叙事闭环）
3. **辩论只发争议点**（兑现文档里"省 70% token"的设计，也是唯一能讲"我优化了 token"的实证点）

**然后才是那 40 道校准**——它是护城河，也是唯一必须你亲自做的事。

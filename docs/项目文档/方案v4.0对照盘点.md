## 五、方案其他部分的落地情况

### 5.1 第二部分（Open Core 开源策略）

| 方案设想 | 实际 | 判断 |
|---|---|---|
| 公开层：框架 + **3 道种子题** | 公开层给了**40 套 181 题**（国考 24 + 河北省考 16） | **比方案更开放**。分界线从"3 道种子题"改成"按年份 ≤2021"——传播力更强，私有层锚定在 ≥2022 新题上 |
| 私有仓库 `bluepencil-core/`（另建仓库） | **没建第二个仓库**，同仓用 `.gitignore` + `@private-*` 别名隔离（`real-exams-private/`、`standards-private/`、`私有题库/`） | 口子在：**私有资产靠忽略规则挡住，就有漏的风险**（项目里已因此写过规则："私密资产不要靠别人的忽略规则顺带挡住"）。真要商业分发，独立仓库更稳 |
| AGPL-3.0 + 混淆 | AGPL-3.0 ✅ + 每份核心文件带作者注释头 ✅；**混淆没做** | 混淆与"开源可审计"本身有张力，实际选择了不混淆 |
| README 声明（开源范围/不包含/获取完整题库） | 🟡 → ✅ | 原本有"公开/私有分层表"，但缺方案要求的「**不包含**：私有题库 / 评分标准 / .bpq 工具」显式段落，<br>且数字过时（写着"私有 9 套 45 题"，实际 13 套 58 题）。**本次盘点已一并修好** |

### 5.2 第四部分（微信二维码）

- **展示位置 4/6**：侧边栏 ✅、首页 ✅、设置页 ✅、**题库页（导入入口旁）✅**；
  缺「首次启动引导页」与「批改结果页小字提示」（项目里没有独立的"关于页面"，由设置页承载）
- **配置方式变了**：方案用 `src/assets/config.json`，实际用 `data/wechat.js`（JS 模块，单一来源）—— 原因：二维码必须 `import` 不能放 `public/`（单文件版会裂图且不报错）

- **群码过期换图**：机制有（`groupExpireAt`），**但需要人工每 7 天换图重打包**（运营性待办）

### 5.5 附录 A（数据结构）——差异最大的一块

**GradingPoint 逐字段对照**（这是方案里最"实"的规格，也是最值得补的）：

| 方案字段 | 实际 | 影响 |
|---|---|---|
| `id` / `content` / `score` / `keywords` / `evidence` | ✅ 有（`content`→`label`、`score`→`weight`、`evidence` 是字符串数组） | — |
| **`type`（main_point / bonus_point / forbidden_point）** | ❌ **未实现** | **最有价值的一项缺失**：没有"禁止点"，就挡不住"方向写错却因为命中关键词得分" |
| **`synonyms`（同义词）** | ❌ **未实现** | 考生用近义词表达同一要点时，采分容易漏判——这是"评分准不准"的直接变量 |
| `required`（必需项） | 🟡 隐含在 `note` 文字里（"不写 XX 不给分"），非结构化 | 无法程序化判定"必需项缺失" |
| `evidence[{material, text, position, verified}]` | 🟡 `evidence` 是字符串数组，无 material 号 / 位置 / 已核验标记 | 无法做"依据是否真在材料里"的自动核验 |

**Question / BPQHeader 差异**：方案是扁平 `Question` 接口，实际是「套卷 + 题」两级
（`exam-<id>.js` = `{id, year, paper, title, tier, system, material, questions[]}`）；
`BPQHeader` 的 `expiresAt` / `deviceBinding` / `standardVersion` 字段未实现。

| 7 | 微信入口补齐 2 处（首启引导、结果页提示）+ 备用联系方式 | 第四部分 | 小 | 无 |
| 8 | 授权码 / 设备绑定（授权模式 C、D） | 第五部分 | 中等 | 只有要做强分发控制才需要 |
| 9 | 独立私有仓库 | 第二部分 | 小（但涉及历史迁移） | 商业分发前再动 |
| 10 | 定价与付费流程 | 第七部分 | — | 属于商业决策，不是开发项 |

---

## 七、结论

**做到了方案的主体，而且有几处做得比方案更实**：公开层从"3 道种子题"扩到"40 套真题"、
错题本/再练一题/可信度这些 V3 项都超出方案描述的质量要求（无依据不推荐、不适用不硬编）、
另外还多做了方案里没有的东西（管理员端 GUI、一键回归 19 套测试、材料按题裁剪、河北省考整省入库）。

**但方案里权重最高的那一件事没做**：那 40 道题的采分点校准。
其余缺口（用户侧导入、大作文档级、Token 预算制、schema 的 forbidden_point/synonyms）
都是"再花时间就能做"，只有校准这件事**必须你本人投入**，而且它决定了其他优化有没有意义
——评分标准不准，后面所有打磨都是在没校准的地基上盖楼。

**建议的下一段路**：先花两三个晚上校准 5~10 道近年国考题（用 `--draft` 出草稿能省一半时间），
拿真实批改结果对比"有标准 / 无标准"的稳定性，把这块地基夯实；然后再做大作文档级诊断。

**关系**：一份设计的三次表述迭代，**没有互相矛盾的决策**，只是详略与侧重不同。
所以合并方式是：**按主题归并**（评分内核 / 练习形态 / 训练闭环 / 题库内容 / 分发体系 / 工程质量），
不按文档来源组织——写代码的人只需要知道"这件事本身做没做"，不需要记得它在哪份文档里。

| 2 | **A2 硬规则前置进老师 prompt** | 一个参数传递的事，让"确定框架"叙事闭环 |
| 3 | ⚠️ **A1 实测后判定不做**（2026-09-24）：量出来的上限是 17.1%，且 debate 历史上从未触发 —— 见下方实测记录 | 实测代替动手：**避免了做一件收益接近 0、还要冒"辩论失去原文判据"风险的改动** |
| 4 | ✅ **A5 可信度加来源维度 + A6 schema 补 synonyms/forbidden_point**（2026-09-24 完成） | 直接提升分数可信度与采分准确率 |

| 7 | **E3 性能实测 + F3 溯源手册** | 顺手做掉，面试可展示、分发有据可依 |

> **A1 实测记录（2026-09-24，离线构造与流水线同源的 message 测得）**
> 一次三师圆桌假设触发辩论时：grade 3 次共 9,935 tokens（占整题 70%），
> debate 2,060 + fuse 2,294（占 30%）；其中 **paper 分别占两者 user 内容的 71.8% / 72.5%**。
> 即便辩论与合议完全不重发 paper，也只省 2,450 tokens ＝ **整题 17.1%**。
> 三个原因让这项优化的实际价值远低于文档预期：
> ① 材料早已按题裁剪（本卷 6887→1651 字，省 76%），"整份重发"的绝对量本就很小；
> ② debate 需得分率极差 > 15% 才触发，**记账表里历史上一次都没触发过**；
> ③ debate/fuse 里的 paper 是**判据**——去掉它，辩论会退化成"两个分数谁对"的空对空。
> → **实测的价值在于拦住一次收益接近 0 的改动**，而不是"少做一件事"。

**做完阶段一的验收**：19 套测试全绿 + 新增护栏；`test-all` 覆盖新逻辑；
一篇「阶段一交付说明」记清改了什么、为什么这么改。

### 阶段二：需要你参与 —— **校准与实测**

目标：把"准不准"从猜测变成数据。**这是唯一必须你本人投入的部分。**

| 顺序 | 任务 | 为什么必须你来 |
|---|---|---|
| 1 | **D1 先说 5~10 道试点校准**（不是一上来 40 道） | 采分点是专业判断，只有你能定；工具已就绪，`--draft` 出草稿能省一半时间 |
| 2 | **E1 跨次一致性实验**：同一份作答、同一道题、批两次，比对得分与采分点命中 | 有了标准才能测；这是"可复算"最硬的证据 |
| 3 | **E2 成本样本扩大**：不同题型批 10~20 次，得出成本与 token 分布 | 花的是你的 Key（约 ¥1 内），需要你的额度 |
| 4 | 视试点结果决定是否把校准推到 40 道 | 如果"有标准 vs 无标准"的差异不明显，就先别扩大投入 |
| 5 | 校准有覆盖之后，再做 **A4 采分点级分歧检测 + A5 老师逐点判定** | 这两项要有采分点列表才能落地；先做等于给一道没有标准的题造检查表 |

**做完阶段二的验收**：能拿出一张表——「有标准 / 无标准」在同一批作答上的分数稳定性对比。

### 5.2 面试可以展示什么

- **19 套自动化测试 + 260+ 条断言**，一条命令全绿（含"起真 exe 验渲染"的探针）

  —— 这套方法是从真实事故里总结的（探针连上别人的实例、构建产物全绿但屏幕是错误页）
- **纯代码层不依赖模型**：硬规则引擎零依赖、可单测、扣分封顶只作旁证
- **数据分层与加密分发**：AES-GCM + ECDSA + 逐用户水印 + 口令批次 + 台账 sha256
- **一条讲得清的叙事**：不是"我调了个大模型"，而是**"我怎么把不确定的 LLM 关进确定的框架里"**

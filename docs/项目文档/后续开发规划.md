## 〇、一页速览

**三个一句话**：

1. **现状**：可分发、可复算的申论 AI 批改工具（网站版 / 单文件版 / 桌面版三产物），
   **「练 → 改 → 评 → 复盘 → 学」闭环齐备**（M 系列过半落地：精读训练、全屏三栏、
   工作台、素材本 180 条、学习周报）；自动化测试 **28/28 套**全绿；性能三项实测全达标。
2. **诊断**：「最好的批改器 + 能用的备考台」已经成立；下一程的短板在两处——
   **数据资产没有备份出口**（用户练一年的记录，一次清缓存就没了）和
   **错题只记不重练**（错题本记下了，但没有"隔几天重做"的机制）。
   最深的护城河仍是**采分点校准覆盖率**（1/239，只有你能动）。
3. **下一步**：两条线并行——**你**做 D1 采分点校准（唯一我替代不了的事）；
   **我**做 M10 一键备份恢复 → M11 错题重测 → M12 动态任务卡 → M5 攻略 → M6 目标分 → M3 仿写。

**总路线图**：

| 泳道 | 内容 | 谁做 | 详见 |

| **泳道 1 · 校准与实测** | D1 校准试点（5~10 道）→ E1 一致性实验 → E2 成本样本 → 视结果扩到 40 道 → A4 采分点级分歧 | **你**（我出工具与对比表） | [2.1](#21-泳道-1校准与实测--需要你) |

## 二、路线图（三条泳道）

### 2.1 泳道 1：校准与实测 —— 需要你

> 目标：把"准不准"从猜测变成数据。**这是唯一必须你本人投入的部分**，
> 也是三份方案里唯一被点名"护城河"的东西。

| 顺序 | 任务 | 说明 |
|---|---|---|
| 1 | **D1 试点校准 5~10 道**（不是一上来 40 道） | 采分点是专业判断，只有你能定；工具已就绪：`node .tools/standards/calibrate.mjs --wizard <题id>`，`--draft` 出本地启发式草稿能省一半时间。建议从内置仿真题与高频练习真题里挑 |
| 2 | **E1 跨次一致性实验** | 同一份作答、同一道题、批两次，比对得分与采分点命中；目标 ≥85%——"可复算"最硬的证据 |
| 3 | **E2 成本样本扩大** | 不同题型批 10~20 次（约 ¥1 内），得出真实 token/成本分布；验收线靠它 |
| 4 | **扩不扩到 40 道** | 视试点结果：如果"有标准 vs 无标准"差异不明显，先别扩大投入 |
| 5 | **A4 采分点级分歧检测** | 校准有覆盖之后才做——没有采分点列表，它无处施展 |

**验收**：拿出一张表——「有标准 / 无标准」在同一批作答上的分数稳定性对比。

### 2.2 泳道 2：一站式备考模块（M 系列）—— 我做

> 产品判断：提分的下一程不是加更多批改功能，而是补上"每天打开该干什么"
> 和"找不到点、写不出规范话"两个真痛点。

**痛点 → 模块映射**：

| 用户痛点（原话级别） | 对应模块 | 提分逻辑 |

| "材料读了三遍还是找不全要点" | **M4 材料精读训练** | 划要点 → 与采分点对照，练的就是"哪些话是答案" |
| "一边看材料一边写要来回切换" | **M8 全屏三栏作答** | 读材料 → 列提纲 → 落笔三区同屏，设计规格见第三章 |

### 2.3 下一程（M10~M12）—— 2026-10-10 新增

> 回答"感觉还差点东西"：M 系列前六个模块落地后做了一次系统性盘点，
> 差的不是更多功能，而是三件"用了很久之后才会痛"的事——
> **数据会丢、错题不重练、任务卡不会跟着人变**。

#### 核心竞争力对标（2026-10-10，随升格引擎落地补充）

对标粉笔/华图 AI 批改（给分 + 评语 + 参考答案），我们的代差不在「更多模块」，
而在三件别人没有、且互相咬合的东西：

1. **升格引擎 E1 ✅（v0.34.0）**——不止评"哪句差"，而是逐句搭桥：
   你的原句 → 问题定性（12 类口径）→ 可直接替换的升格句 → 理由 → 融合全部改写的
   升格全文。这是人工批改班最贵的「逐句精批 + 升格示范」的自动化，一次调用、随记录存档、
   复盘页可回看。**这是考生愿意付费的那个瞬间。**
2. **可信度可复算**——每个分数带「依据链」：硬规则纯代码可复算、标准来源诚实标注
   （AI 预解析 vs 人工精校）、六信号可信度、结果冻结（标准/提示词/模型/温度版本）。
   竞品给一个黑盒分数，我们给一份能回答"这个分怎么来的"的卷宗。
3. **标准校准管线（D1 的解法，→M13）**——精读/批改的天花板是标准质量。
   现状 158 道标准全部为 glm-4-flash 单模型预解析（已证据校验、未人工精校），
   精读页已加「未人工精校」诚实提示。下一步：**AI 交叉校准起草器**
   （2~3 个模型独立起草采分点 → 纯代码比对共识 → 高共识自动入库、低共识进
   校准工作台人审）——把 D1 的 239 道从「逐题手写」变成「逐题审签」，
   这是内容质量的护城河，也是竞品最重难抄的部分。

#### M10 一键备份与恢复（先做，工作量 S）

**为什么是它**：用户的全部资产——作答、批改记录、荧光、收藏、提纲、打卡——
都存在浏览器 IndexedDB（桌面版部分落在 exe 同级 `data/`）。练一年的记录，
一次「清除浏览器数据」、一次重装系统就全没了，**没有任何出口**。
对一个定位"陪你备考到上岸"的工具，这是信任地基，不是锦上添花。

| 设计点 | 方案 |
|---|---|
| 备份内容 | IndexedDB 六个 store 全量 + localStorage 键值（荧光/收藏/提纲/偏好），打成单个 `.bpb`（BluePencil Backup）JSON |
| 格式 | 带 `magic`/`version`/`exportedAt`/`counts` 头部——恢复前先校验再写入，坏文件明确报错不静默 |
| 恢复策略 | **合并而非覆盖**（按 id 去重，冲突取较新），恢复前弹确认显示"将导入 N 条记录" |
| 入口 | 设置页「数据」区：导出备份 / 导入备份，各一行 |
| 验收 | 护栏：备份→清库→恢复→记录数与内容一致的往返测试；探针：真浏览器导出下载 + 导入回显 |

#### M11 错题重测（工作量 S）

**为什么是它**：错题本把错题**记**下来了，推荐下一题也做了，但缺最后一环——
**隔几天把错过的题再练一遍**。遗忘曲线是备考的基本盘，"记了不重练"的错题本
只是个清单。复用度极高：错题本数据、批改链路、记录对比全是现成的。

| 设计点 | 方案 |
|---|---|
| 触发 | 错题本每条错题带"上次出错时间"；≥3 天的错题在 M1 任务卡出现「重测 1 题」 |
| 重测 | 进入原题的**空作答**状态（看得到原批改但默认折叠，防止照抄） |
| 闭环 | 重测批改后，错题本该条记录"重测成绩"，连续两次全对自动淡出推荐 |
| 诚实原则 | 没有错题就闭嘴，不硬造"该复习了" |
| 验收 | 护栏：错题筛选/淡出规则纯函数单测；探针：重测入口只在有 ≥3 天错题时出现 |

#### M12 动态任务卡（工作量 M）

**为什么是它**：M1 的三张任务卡（练一题/精读一则/积累一组）是**固定**的——
练了三天后它就只是打卡器。周报是**回顾**（上周怎么了），缺**前瞻**
（今天该练什么）。把画像弱项、错题积压、连续未练的题型喂给任务卡，
工作台才真正"认识你"。

| 设计点 | 方案 |
|---|---|
| 数据源 | 能力画像（弱维）→ 推弱项题型；错题本（积压）→ 推 M11 重测；周报（趋势）→ 下降时提示 |
| 规则 | 固定三张卡保留为底座，弱项题型卡**插队**为第一张（有依据才插，沿用推荐两档原则） |
| 诚实原则 | 画像样本 <3、错题为空时保持现状三张——**没依据不开口** |
| 验收 | 护栏：任务排序纯函数单测（弱项/无弱项/样本不足三态）；探针：断渲染出的卡序 |

**顺序理由**：M10 是数据安全（不做它，其他一切积累都有归零风险）；
M11 是闭环收尾（依赖少、见效快）；M12 依赖 M11 的错题积压数据，放最后。

## 三、M8 全屏三栏作答模式 · 设计规格

> 需求来源：作者本人提案——"全屏模式，一边看材料一边写答案：右侧答题区，
> 左侧上下两块，上半看材料做标记，下半列提纲"。
> 下面先分析这个布局的合理性，再给完善后的落地规格。

### 3.1 布局分析：提案对在哪

```
┌────────────────────────────────────────────────────────────┐
│ 生命线（必须保留）：题型 · 计时 · 字数 · 批改按钮 · 退出全屏  │
├───────────────────────────────┬────────────────────────────┤
│ 左上 · 材料（约 70% 高）        │  右栏 · 作答区              │
│  可滚动全文 + 荧光标注          │  题干（小字只读）            │
│  划要点句 / 写批语             │  方格作答纸（主战场）        │
│         ⇅ 拖拽分割线           │  字数 / 交卷                 │
│ 左下 · 提纲（约 30% 高）        │                            │
│  立论 → 分论点(附材料依据)      │                            │
│  ← 荧光句子可一键收进来         │                            │
└───────────────────────────────┴────────────────────────────┘
```

1. **信息动线符合作答心智**：读材料（输入）→ 列提纲（加工）→ 落笔（输出），
   三栏正好是这条流水线，从左到右单向流动、互不遮挡——比现状（提纲在右侧作答区下方，
   写提纲时要滚过作答纸）更顺。
2. **材料在上、提纲在下是对的**：提纲条目普遍要标"材料依据"，与材料上下相邻便于对照；
   若提纲在材料右边则视线来回横跳。
3. **全屏切掉导航壳是净收益**：答题页当前 `calc(100vh-32px)` 已经很挤，
   再省出导航条高度，左栏材料可视行数直接多 2~3 行——申论材料几千字，每行都值钱。

### 3.2 三个坑（直接照抄提案会栽的地方）

| # | 坑 | 完善方案 |
|---|---|---|
| 1 | **五五开的高度分配是错的**。材料动辄五六千字、提纲两百字，等分会造成"材料滚不到底、提纲空一半" | 默认 **7:3**，分割线可拖拽，比例按题目记忆（localStorage） |
| 2 | **宽屏假设**。1366×768 的笔记本硬拆三栏，每栏都读不了 | `≥1280px` 才出三栏；1024~1280 降级为现有两栏 + 提纲浮动抽屉；<1024 维持现状（单列） |
| 3 | **全屏把生命线也藏了**。交卷、计时、字数被"沉浸"掉 = 考场事故 | 顶部留一条**不可隐藏的生命线**（题型/计时/字数/批改/退出），只藏导航与页壳；Esc 与按钮双通道退出，状态持久化 |

### 3.3 提案之外的三个增强（三栏布局独有的杠杆）

- **荧光句子 → 提纲一键收进**：在材料上划的句子，点击"收进提纲"变成提纲条目
  （自动带材料定位，点条目材料滚到对应位置）。这是"边读边记"的关键一步，
  也是 M4 找点训练共用的基建——同一套标注锚点，练习时是批注，全屏时是素材，M4 里是答案候选。
- **提纲字数预算**：提纲条目旁按目标字数显示"这行大概值多少字"（如分论点 250 字/条），
  防止提纲写飞与正文脱节。纯本地计算，零成本。
- **左栏宽度可拖**：大作文时材料利用率低，可以把左栏收窄给作答区让位；
  概括题反之。默认 32rem（现有验证过的舒适行宽），可调范围 24~40rem，记忆偏好。

### 3.4 落地拆解与护栏

| 步骤 | 内容 | 验收 |
|---|---|---|
| 1 | 答题页加"全屏"开关（路由不变，视图状态持久化），隐藏导航/页壳，生命线保留 | 全屏后 `100vh` 内无滚动条穿帮（复用 test-one-screen 思路） |
| 2 | 左栏纵向拆分：材料（Highlightable 复用）+ 分割线 + 提纲（现有 `bp-outline` 存储复用） | 拖拽后刷新页面比例保持；提纲内容跨模式不丢 |
| 3 | 降级层：<1280 两栏 + 提纲抽屉；<1024 单列现状 | 三档截图探针各验一张 |
| 4 | 荧光 → 提纲收进 + 字数预算 | 收进的条目带材料定位，点条目材料滚到对应位置 |
| 5 | 护栏 | probe-layout-overlap 扩展三栏形态；断言"生命线在全屏态可见"；断言提纲/标注存储键不回归 |

> ⚠️ 老规矩两条：① flex/grid 定高逐层检查 `min-h-0` 链（v0.24/0.26 两次栽在这）；
> ② 程序化起 dev server 必须 cwd=frontend，否则 Tailwind 全消失、探针红得莫名其妙。

### 5.2 面试可以展示什么

## 附录 B：重要实测与坑记录

**B-1 · A1 辩论不重发 paper：实测后不做（2026-09-24）**
离线构造与流水线同源的 message 测得：grade 3 次共 9,935 tokens（占整题 70%），
debate 2,060 + fuse 2,294（占 30%）；paper 占两者 user 内容的 71.8% / 72.5%。
即便完全不重发也只省 2,450 tokens = 整题 17.1%。三个原因：
① 材料早已按题裁剪（6887→1651 字，省 76%），绝对量本就小；
② debate 需得分率极差 >15%，记账表里历史从未触发；
③ debate/fuse 里的 paper 是判据——去掉它辩论退化成"两个分数谁对"的空对空。
**实测的价值在于拦住一次收益接近 0 的改动。**

**B-2 · A7 highlights 的两个存放位置（都已写成护栏）**
① 结果页传的是 orchestrator 的 `report`（在 `final` 里），记录页传的是 `buildRecord` 的结果（已提到顶层）——只认一种，"做得好"在另一侧永远是空且不报错；
② 契约里它是条件性字段，多数老师不输出；真正的主来源是合议综合的那一份（`fusion.highlights`）。

**B-3 · C1/C2 顺带修掉的两个既有 bug**（都是"不报错、只是数字悄悄错"）
① 「自建 N 道」把题库包导入的私有真题也算进去（导入 13 套后凭空多 58）；
② 私有卷数用 `Math.max` 单调累加，删除批次后不回落。改为：`mine` 保留全部用户侧题、
「自建」单独计数、私有卷数按卷 id 去重取并集。

## 〇、一页速览

**三个一句话**：

1. **现状**：可分发、可复算的申论 AI 批改工具（网站版 / 单文件版 / 桌面版三产物），
   **「练 → 改 → 评 → 复盘」闭环齐备**；自动化测试 24/24 套全绿；性能三项实测全达标。

   **我**做 M 系列一站式备考模块（M4 精读起步，M8 全屏三栏紧随）。

## 二、路线图（三条泳道）

### 2.1 泳道 1：校准与实测 —— 需要你

> 目标：把"准不准"从猜测变成数据。**这是唯一必须你本人投入的部分**，
> 也是三份方案里唯一被点名"护城河"的东西。

| 顺序 | 任务 | 说明 |
|---|---|---|
| 1 | **D1 试点校准 5~10 道**（不是一上来 40 道） | 采分点是专业判断，只有你能定；工具已就绪：`node .tools/standards/calibrate.mjs --wizard <题id>`，`--draft` 出本地启发式草稿能省一半时间。建议从内置仿真题与高频练习真题里挑 |
| 2 | **E1 跨次一致性实验** | 同一份作答、同一道题、批两次，比对得分与采分点命中；目标 ≥85%——"可复算"最硬的证据 |
| 3 | **E2 成本样本扩大** | 不同题型批 10~20 次（约 ¥1 内），得出真实 token/成本分布；验收线靠它 |
| 4 | **扩不扩到 40 道** | 视试点结果：如果"有标准 vs 无标准"差异不明显，先别扩大投入 |
| 5 | **A4 采分点级分歧检测** | 校准有覆盖之后才做——没有采分点列表，它无处施展 |

**验收**：拿出一张表——「有标准 / 无标准」在同一批作答上的分数稳定性对比。

### 2.2 泳道 2：一站式备考模块（M 系列）—— 我做

> 产品判断：提分的下一程不是加更多批改功能，而是补上"每天打开该干什么"
> 和"找不到点、写不出规范话"两个真痛点。

**痛点 → 模块映射**：

| 用户痛点（原话级别） | 对应模块 | 提分逻辑 |
|---|---|---|
| "材料读了三遍还是找不全要点" | **M4 材料精读训练** | 划要点 → 与采分点对照，练的就是"哪些话是答案" |
| "一边看材料一边写要来回切换" | **M8 全屏三栏作答** | 读材料 → 列提纲 → 落笔三区同屏，设计规格见第三章 |
| "写的都是大白话，不会规范表述" | **M2 素材本 / 规范词库** | 阅卷采分看关键词，规范词背一组顶十篇时评 |
| "大作文展不开论证" | **M3 范文对照仿写** | 抄写→仿写→批改，把时评从"读过"变成"会写" |
| "不知道每天该学什么" | **M1 学习中心** | 每日任务卡把存量功能串成闭环 |
| "练了半个月不知道有没有进步" | **M6 目标分追踪 + M7 学习周报** | "距目标差多少" + "这周干了什么" |

**模块清单（按推荐顺序）**：

| # | 模块 | 做什么 | 工作量 | 依赖/复用 | 验收要点 |
|---|---|---|---|---|---|
| **M4** ✅ | **材料精读训练**（2026-10-08，v0.28.0）| 划要点句 → 对照采分点出"找点得分率"（按分值加权）+ 命中点数 + 误划数；漏点原文红色叠加在材料上；选题池**由标准注册表派生**（校准一道自动多一道）；无标准题降级自由精读并明示 | **M** | 荧光标注基建 + 采分点标准层全复用，匹配是纯代码（`pointMatch.js`）零 LLM 成本 | 护栏：`test-read-match.mjs` 22 项 + `probe-read-ui.mjs` 14 项 |
| **M8** | **全屏三栏作答** | 左栏上下两块（材料+标注 / 提纲），右栏作答区；拖拽调比例；荧光句一键收进提纲。**设计规格见第三章** | M | 荧光标注 + 提纲存储（`bp-outline:<qid>`） | 三档宽度降级正确；生命线全屏态可见；比例与内容持久化 |
| **M1** | **学习中心（首页改造）** | 静态着陆页 → 工作台：备考倒计时（自填目标日期）+ 打卡 streak + 今日任务卡（练一题/精读一则/积累一组，点击直达）+ 画像速览 + 最近成绩 | M | 汇总现有画像/每日一练/记录数据，零新数据 | 任务卡状态与真实数据一致（做完的任务不假装没做） |
| **M2** ✅(v1) | **素材本 / 规范词库**（2026-10-08，v0.28.0）：72 条规范表述按 9 主题对照编排（与文章库口径对齐）+ ⭐收藏 + **A4 打印导出**（衬线/题头/防断页，另存 PDF 即导出）。🟡 批注好句一键收藏待后续 | **M** | 内容新增 + localStorage 收藏 + print 媒体样式 | 护栏：`probe-lexicon-ui.mjs` 11 项（含 print 换装与 PDF 分页） |
| **M7** | **学习周报** | 每周一篇纯本地生成：练了几题、得分率变化、高频错误类型、下周建议（规则引擎，**零 LLM 成本**） | S | error-taxonomy / profile 口径 | 数据不足时明说"样本不够"，不硬编 |
| **M5** | **题型攻略** | 5 份讲义按题型重组为五篇攻略（评分侧重 + 常见错误 + 例题直达练习） | M | 内容重组（讲义已有） | 每篇攻略至少 3 个"直达练这题"链接真实可跳 |
| **M6** | **目标分追踪** | 设置目标分/进面线；StatsView 加"距目标差 X 分 + 六维里最该补哪维"（**没依据不说**，沿用推荐两档原则） | S | StatsView 已有趋势与画像 | 未设目标不显示；建议必须有依据（≥2 份记录） |
| **M3** | **范文对照仿写** | 时评/参考答案与自己的作答左右对照；"抄写→仿写→AI 点评"三步（复用小题批改契约） | L | 依赖 M2；批改链路复用 | 仿写点评复用既有批改入口，不另起契约 |

**推进节奏**：M4 → **M8 → M1** → M2 → M7 → M5 → M6 → M3。
理由：M4 是唯一"训练能力"而不只是"展示信息"的新功能，且复用度高；
M8 与 M4 共享标注基建、又是用户待得最久的作答页（紧随其后）；
M1 把所有东西串起来（一站式的脸面）；M2 内容型可穿插；M3 最重，放最后。

## 三、M8 全屏三栏作答模式 · 设计规格

> 需求来源：作者本人提案——"全屏模式，一边看材料一边写答案：右侧答题区，
> 左侧上下两块，上半看材料做标记，下半列提纲"。
> 下面先分析这个布局的合理性，再给完善后的落地规格。

### 3.1 布局分析：提案对在哪

```
┌────────────────────────────────────────────────────────────┐
│ 生命线（必须保留）：题型 · 计时 · 字数 · 批改按钮 · 退出全屏  │
├───────────────────────────────┬────────────────────────────┤
│ 左上 · 材料（约 70% 高）        │  右栏 · 作答区              │
│  可滚动全文 + 荧光标注          │  题干（小字只读）            │
│  划要点句 / 写批语             │  方格作答纸（主战场）        │
│         ⇅ 拖拽分割线           │  字数 / 交卷                 │
│ 左下 · 提纲（约 30% 高）        │                            │
│  立论 → 分论点(附材料依据)      │                            │
│  ← 荧光句子可一键收进来         │                            │
└───────────────────────────────┴────────────────────────────┘
```

1. **信息动线符合作答心智**：读材料（输入）→ 列提纲（加工）→ 落笔（输出），
   三栏正好是这条流水线，从左到右单向流动、互不遮挡——比现状（提纲在右侧作答区下方，
   写提纲时要滚过作答纸）更顺。
2. **材料在上、提纲在下是对的**：提纲条目普遍要标"材料依据"，与材料上下相邻便于对照；
   若提纲在材料右边则视线来回横跳。
3. **全屏切掉导航壳是净收益**：答题页当前 `calc(100vh-32px)` 已经很挤，
   再省出导航条高度，左栏材料可视行数直接多 2~3 行——申论材料几千字，每行都值钱。

### 3.2 三个坑（直接照抄提案会栽的地方）

| # | 坑 | 完善方案 |
|---|---|---|
| 1 | **五五开的高度分配是错的**。材料动辄五六千字、提纲两百字，等分会造成"材料滚不到底、提纲空一半" | 默认 **7:3**，分割线可拖拽，比例按题目记忆（localStorage） |
| 2 | **宽屏假设**。1366×768 的笔记本硬拆三栏，每栏都读不了 | `≥1280px` 才出三栏；1024~1280 降级为现有两栏 + 提纲浮动抽屉；<1024 维持现状（单列） |
| 3 | **全屏把生命线也藏了**。交卷、计时、字数被"沉浸"掉 = 考场事故 | 顶部留一条**不可隐藏的生命线**（题型/计时/字数/批改/退出），只藏导航与页壳；Esc 与按钮双通道退出，状态持久化 |

### 3.3 提案之外的三个增强（三栏布局独有的杠杆）

- **荧光句子 → 提纲一键收进**：在材料上划的句子，点击"收进提纲"变成提纲条目
  （自动带材料定位，点条目材料滚到对应位置）。这是"边读边记"的关键一步，
  也是 M4 找点训练共用的基建——同一套标注锚点，练习时是批注，全屏时是素材，M4 里是答案候选。
- **提纲字数预算**：提纲条目旁按目标字数显示"这行大概值多少字"（如分论点 250 字/条），
  防止提纲写飞与正文脱节。纯本地计算，零成本。
- **左栏宽度可拖**：大作文时材料利用率低，可以把左栏收窄给作答区让位；
  概括题反之。默认 32rem（现有验证过的舒适行宽），可调范围 24~40rem，记忆偏好。

### 3.4 落地拆解与护栏

| 步骤 | 内容 | 验收 |
|---|---|---|
| 1 | 答题页加"全屏"开关（路由不变，视图状态持久化），隐藏导航/页壳，生命线保留 | 全屏后 `100vh` 内无滚动条穿帮（复用 test-one-screen 思路） |
| 2 | 左栏纵向拆分：材料（Highlightable 复用）+ 分割线 + 提纲（现有 `bp-outline` 存储复用） | 拖拽后刷新页面比例保持；提纲内容跨模式不丢 |
| 3 | 降级层：<1280 两栏 + 提纲抽屉；<1024 单列现状 | 三档截图探针各验一张 |
| 4 | 荧光 → 提纲收进 + 字数预算 | 收进的条目带材料定位，点条目材料滚到对应位置 |
| 5 | 护栏 | probe-layout-overlap 扩展三栏形态；断言"生命线在全屏态可见"；断言提纲/标注存储键不回归 |

### 5.2 面试可以展示什么

- **24 套自动化测试 + 300+ 条断言**，一条命令全绿（含"起真 exe 验渲染"的探针）

  —— 从真实事故总结（探针连上别人的实例、构建产物全绿但屏幕是错误页）
- **纯代码层不依赖模型**：硬规则引擎零依赖、可单测、扣分封顶只作旁证

- **一条讲得清的主线**：不是"我调了个大模型"，而是**"我怎么把不确定的 LLM 关进确定的框架里"**
- **成本叙事**：全部 M 模块零新增 LLM 成本（M3 复用既有批改链路）——"纯代码不花用户钱"

## 附录 B：重要实测与坑记录

**B-1 · A1 辩论不重发 paper：实测后不做（2026-09-24）**
离线构造与流水线同源的 message 测得：grade 3 次共 9,935 tokens（占整题 70%），
debate 2,060 + fuse 2,294（占 30%）；paper 占两者 user 内容的 71.8% / 72.5%。
即便完全不重发也只省 2,450 tokens = 整题 17.1%。三个原因：
① 材料早已按题裁剪（6887→1651 字，省 76%），绝对量本就小；
② debate 需得分率极差 >15%，记账表里历史从未触发；
③ debate/fuse 里的 paper 是判据——去掉它辩论退化成"两个分数谁对"的空对空。
**实测的价值在于拦住一次收益接近 0 的改动。**

**B-2 · A7 highlights 的两个存放位置（都已写成护栏）**
① 结果页传的是 orchestrator 的 `report`（在 `final` 里），记录页传的是 `buildRecord` 的结果（已提到顶层）——只认一种，"做得好"在另一侧永远是空且不报错；
② 契约里它是条件性字段，多数老师不输出；真正的主来源是合议综合的那一份（`fusion.highlights`）。

**B-3 · C1/C2 顺带修掉的两个既有 bug**（都是"不报错、只是数字悄悄错"）
① 「自建 N 道」把题库包导入的私有真题也算进去（导入 13 套后凭空多 58）；
② 私有卷数用 `Math.max` 单调累加，删除批次后不回落。改为：`mine` 保留全部用户侧题、
「自建」单独计数、私有卷数按卷 id 去重取并集。

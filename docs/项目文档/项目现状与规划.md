## 〇、一页速览

**这是什么**：一个面向公考申论的 AI 批改工具 —— 五位名师 Agent 独立阅卷、分歧才辩论、
加权合议出分；分数有采分点锚点、有纯代码校验兜底、有可信度指标。
本地优先（作答与记录都在本机），三种形态分发：网站版 / 单文件 HTML / **桌面版 exe（9.6 MB，双击即用）**。

**当前家底**：

| 维度 | 现状 |
|---|---|
| 题库 | **53 套 / 239 题**（公开 40 套 181 题：国考 24 套 + 河北省考 16 套；私有 13 套 58 题） |
| 内容 | 仿真题 15 道、官媒时评文章 31 篇（约 9.5 万字） |
| 阅卷 | 5 位老师、1~5 人任意组合，圆桌分歧才辩论 |
| 练习 | 练习批改（训练）+ **考场模式**（独立入口、计时交卷） |
| 复盘 | 历史批改 / 统计 / 错题本 / 能力画像（六维雷达） |
| 测试 | **19 套自动化测试全绿**（18 个前端套件 + pytest 22 项），发版前一条命令 |
| 产物 | 桌面版 v0.19.1（9.6 MB）、管理员端 GUI（作者专用） |

**一句话判断**：**功能面已经"能用了"，短板从"能不能跑"变成了"分数准不准"** ——
真实 API 已跑通（单人 ¥0.0147 / 三师圆桌 ¥0.054，实测 60~120 秒），
但**采分点标准只人工精校了 1 道题**，239 道题的评分锚点绝大多数还是机器生成的粗稿。
下一步的重点不是加功能，是**校准**。

## 一、现在能实现的功能

> 表里每一项都在 v0.19.1 打包产物里实测过，不是"代码写了"。

### 1.1 答题与批改

| 能做什么 | 说明 |
|---|---|
| 从题库刷题并作答 | 53 套真题（国考 + 河北省考）+ 15 道仿真题；可按来源 / 体系 / 题型三级筛选 |
| 只看题目要用的材料 | 整卷材料自动裁到「本题引用的那几则」（实测材料省 79%），也可一键切回整卷 |
| 方格纸作答 | 按字数自动分页，字数实时统计 |
| 五位老师任选 | 1~5 人任意组合：单人快、双人对照、三师圆桌、五师圆桌、深度模式 |
| 逐句批注 | 老师各自颜色标在作答原文上，同句多人标中会分段着色；每师另给「只改一处先改哪里」 |
| 圆桌辩论记录 | 分歧 >15% 才触发辩论，辩论过程与裁定逐条可看 |
| 结果四层展示 | 总分与圆桌说明 → 可信度（五信号）→ 六维分项与批注 → 老师意见与辩论记录 |
| 纯代码客观校验 | 字数 / 格式 / 结构 / 重复照抄，只作旁证、扣分封顶 20%、不改写 AI 分数 |
| 采分点对照 | 有标准的题会显示"该采哪些点、你答到几个"（标准本身永不出现在界面上） |

### 1.2 两种练习形态（v0.19.1 起分开）

| 形态 | 入口 | 特点 |
|---|---|---|
| **练习批改** | 侧边栏「实战 → 练习批改」 | 随时批改、随时看参考答案，适合日常消化 |
| **考场模式** | 侧边栏「实战 → 考场模式」 | 落笔即计时（大作文 60 / 贯彻执行 40 / 其余 30，可调）、最后 5 分钟变红、交卷两段确认、时间到自动交卷；作答用时记入报告 |

### 1.3 复盘与成长

- **历史批改**：每次批改的完整记录（含批注、辩论、可信度），可导出 markdown，归档在 `docs/practice/`
- **统计**：练习量 / 平均得分率 / 趋势 / 进步幅度（分数经过越界钳制，不会再出现 300% 这种数）
- **错题本**：按「栽在几份记录里」排序 —— 反复出现的排前面，单发的收进折叠区，只有 1 份记录时明说"还不算反复"
- **能力画像**：固定六维雷达（要点覆盖 / 材料运用 / 结构条理 / 审题应题 / 语言表达 / 规范体例），
  由错误类型反推而非采信老师的自由文本；样本 < 3 不画、每维带依据
- **再练一题**：按短板从题库推下一题，分「同题型对症」与「跨题型通病」两档；判据不足时明确不给推荐

### 1.4 题库与内容管理

- 文章库 31 篇官媒时评，可按主题翻阅
- 每日一练：按本地日期散列，同一天恒定、相邻日期不连号
- **私有题库包（.bpq）导入**：拖进窗口任意位置或点按钮选文件；
  包体 AES-256-GCM 加密 + ECDSA 签名，**导入时先验签再解密**，伪造包直接拒掉
- **作者侧**：打包（含自检）、验包、口令批次发放、发放台账（记 sha256 可事后核对）、按人改水印、
  题库盘点、PDF 提取真题、编入前端、生成汇编、生成数据说明、采分点盘点/校验/草稿/录入、一键回归
  —— 全部收在一个 GUI 里（`release/管理员端/`，与分发版物理隔离）

## 二、已完成（含实现说明）

### 2.1 阅卷内核（项目的分界线）

- **五位真实名师 Agent**（袁东 / 周泰然 / 白鹭 / Kiwi / 李崇立），讲义原文内置，
  每人评审侧重与权重不同 —— 这是"分数会真的分歧"的前提，否则圆桌只是演戏
- **圆桌调度**：并行阅卷 → 分歧检测 → **仅真分歧才辩论** → 加权合议
- **逐句批注契约**：`annotations[{quote, type, comment, fix}]`，quote 必须原样复制原文

### 2.2 评分内核（拆五层，能确定性算的绝不交给模型）

| 层 | 由谁负责 | 状态 |
|---|---|---|
| ① 题目标准层：采分点（分值 · 材料依据 · 判据关键词） | 预解析 / 人工精校，固定复用 | 代码完成，**覆盖待补** |
| ② 模型阅卷层 | 五位老师各自独立 | 完成 |
| ③ 纯代码校验层：字数 / 格式 / 结构 / 重复照抄 | `utils/grading/rules.js`，零依赖 | 完成 |
| ④ 合议层 | 分歧检测 → 辩论 → 加权合议 | 完成 |
| ⑤ 训练层 | 错误类型口径 / 复盘卡 / 错题本 / 画像 / 再练一题 | 完成 |

- **有标准走标准、无标准裸判**，不会因一道题没录标准就罢工
- **最终分出口钳制**（v0.18.0）：单人 / 双人 / 圆桌三条路径统一钳到 [0, 满分]，
  历史脏数据在读档入口自动归一 —— 修掉了"合议 LLM 在 20 分题输出 66 分导致得分率 330%"的根因
- **采分点按公开 / 私有分层**：公开在 `data/standards/`，私有在 `data/standards-private/`（已 gitignore）
  —— 写出采分点等于泄题
- **可信度五信号**（`utils/grading/credibility.js`）：**老师一致性 / 与程序粗判的吻合度 / 阅卷完成度 / 客观校验 / 分歧复核**；
  没依据时显示「不适用」而不是硬编一个数；天花板 96；每个数字带 basis

### 2.3 题库与内容

- **53 套 / 239 题**结构化真题：国考 24 套（2010–2021 公开）+ 13 套（2022 起私有）；
  **河北省考 16 套公开（2008–2021）+ 4 套私有（2022 起）**
- **PDF 提取流水线**：文本提取 → 分题（锚点是「（N分）」而非题号，兼容四种题号写法）→
  结构化 → **六道质量闸门**（材料非空 / 题干要求分值字数非空 / 分值合计 / 答案齐全 / schema）
- **河北卷适配**（v0.19.0）：`【材料一】`/`【问题N】`/三种答案锚点写法/页码与页眉噪声/「不少于N字」；
  改完重提全部国考卷做**内容级 diff 零回归**才放行
- **体系识别单一真源** `data/examSystem.js`：31 省识别 + 国考/省考卷别统一排序口径
- **汇编导出**：`docs/题库/汇编/` 按 体系 / 年份 / 卷别 三级目录，每卷独立 材料 + 参考答案；
  护栏含**采分点泄漏检查**（导出文档里不允许出现任何标准指纹）

### 2.4 分发与加密

- **三种产物**：网站版 `dist/`、单文件 HTML、桌面版 exe（Tauri 2，内嵌前端 + Rust 网关，跨域从根上消失）
- **私有题库包**：AES-256-GCM 正文 + ECDSA P-256 签名（签名覆盖水印，改水印也验不过），
  **先验签再解密**，"泄露可溯源"靠这条
- **口令批次化**：同批人共用一个口令，新批次随机生成，显式复用旧口令会被直接拒绝
- **发放台账**：记「发给谁 / 哪批口令 / 哪个文件 / 文件 sha256」，`--verify-ledger` 可重算核对
- **产物自证版本**：构建注入版本、`health` 接口回报版本；各通道目录只留最新一版、
  往期进该通道自己的 `历史版本/`
- **发包体检** `check_release_private.py`：递归清点产物，报「exam chunk 数 / 有无私有卷 / 功能指纹」
  —— 让文件自己回答，不靠记忆

### 2.5 稳定性护栏（都是被真实事故逼出来的）

- **产物必须真内嵌前端**：`cargo build` 出来的 exe 照样起窗口、进程照样活着，但屏幕是错误页
  → 探针断言 URL 必须是 `tauri.localhost`
- **单实例锁**：两个实例抢 WebView2 数据目录，第二个初始化不出页面 → 单实例 + 探针二次启动检查
- **导入两个入口一条逻辑**：拖拽与按钮共用同一段导入函数，否则迟早有一条忘了处理加密包口令
- **假绿家族三修法**（写进项目记忆）：①显式独立端口/目录 ②起进程前拍基线快照只认新增
  ③被测对象支持"另起一个"参数。`test-md-parity` / `probe-tauri-render` 都加了**秒退检测**
  （作者自己开着软件时单实例会让测试 exe 秒退，报错直接说明原因而不是"CDP 40 秒没起来"）

### 2.6 工程与工具链

- 后端 FastAPI + SQLAlchemy async + SQLite，只做转发 / 并发 / 记账
- 前端 Vue3 + Vite + Tailwind，自然有机风，颜色走语义 token
- **一键回归** `node .tools/test-all.mjs`：自动收集全部前端套件 + pytest，逐套带耗时与统计摘要
- **管理员端 GUI**：11 个工具入口（题库 / 分发 / 文档 / 标准与回归），修掉"点了没反应"
  （Tauri 2 权限声明缺失）与"启动失败 os error 3"（相对路径按父进程目录解析），全程无控制台窗口
- 文档：README、CHANGELOG、使用说明书、管理员端说明、上线部署分析、开发记录、docs 导航

## 三、还没完成

### 3.1 真正的短板：评分校准（不急但最要紧）

| 项 | 现状 | 为什么没做 |
|---|---|---|
| **采分点标准覆盖** | 239 道题里**只有 1 道有人工精校标准**，其余靠批量预解析粗稿 | 需要真实批改结果反推，工作量大（每道题要人工过一遍采分点） |
| **40 道题库校准** | 未开始 | 要先有真 Key 跑批改对比"有标准/无标准"的分数稳定性 |
| **成本与 Token 验收** | 已有实测样本（单人 3422/986 token ¥0.0147；三师 12507/3657 ¥0.054），但**样本量 1~2 次** | 验收线是"常规模式单题 ≤2500 token"（不含材料整卷入参的场景需分开算） |
| 校准工作台 | 工具已就绪（`--list/--check/--draft/--wizard`），**但没人去录** | 这是纯人力活，与代码无关 |

> **一句话**：分数"能出"，但"准不准"没有足够证据。这是从"毕设能演示"走到"敢给人用"之间最大的一步。

### 3.2 题库与内容缺口

| 项 | 说明 |
|---|---|
| 河北 5 卷未入库 | 2004–2007（老版式/疑似扫描件，无文本层）、2021 县级（扫描版**需 OCR**）。已在配置里标 `skip`，不会混进产物 |
| 省考只做了河北 | 你的 PDF 库里有山东（44 份，02–24，卷别最全）、广东等省，管线已通用，加省配置即可，但**内容需要人工核对** |
| 部分卷面本身有瑕疵 | 2009 河北（3 题 80 分）、2018 河北（4 题 90 分）、2015 含判断题 —— 已核对是卷面如此，不是提取错误 |
| 文章库 | 31 篇，无自动更新机制 |

### 3.3 产品功能缺口

| 项 | 说明 |
|---|---|
| **大作文档级约束 / 论证诊断** | 未做。动评分内核，建议等校准有基础后再动（否则改完没法验证效果） |
| 老师档案页 Markdown 渲染 | 现在是纯文本，标题表格都是原样字符 |
| 批改结果导出 Word / PDF | 目前只能导出 markdown |
| 预解析向导的"全自动"部分 | 现有 `--draft` 是启发式草稿（不调模型），没有"模型自动生成采分点候选"那一档 |
| 考场模式的严格性 | 仍允许「换一题」「从题库选题」—— 真实考场是固定卷子，这块待你定 |
| 手写板 / OCR 识图 | 已确认暂不做（优先级最低） |

### 3.4 上线相关（全部未做）

- 访问控制（共享访问码 / OAuth）
- 配额限流 —— **必须按批改次数限**，不能按请求次数限（一次圆桌 = 3~7 次 LLM 调用）
- 服务器部署（Nginx 反代要 `proxy_buffering off`，否则流式会被攒起来）
- 成本上限与熔断（防止 Key 被刷爆）
- 微信交流群二维码每 7 天过期需换图重打包（**运营性待办**）

## 四、后续优化方向

按「投入产出比」排序，都标了工作量与依赖：

| 优先级 | 方向 | 为什么现在做 | 工作量 | 依赖 |
|---|---|---|---|---|
| **P0** | **校准 5~10 道题的采分点标准** | 一次性投入换来"分数可解释"的实证，且它是所有评分优化的前提 | 每题 20~40 分钟（工作台已就绪，`--draft` 先出草稿） | 要你本人判断采分点 |
| **P0** | **录入第二个省份（山东）** | 你的 PDF 库里山东卷最全（02–24），能验证管线复用性、题库直接翻倍 | 配置 1 小时 + 人工核对（每卷 5~10 分钟） | 无 |
| **P1** | 河北 5 卷 OCR 补齐 | 补上 04–07 与 2021 县级，河北就完整了 | OCR 工具链搭建 + 逐卷校对 | 装 OCR（PaddleOCR / 讯飞） |
| **P1** | 大作文档级约束与论证诊断 | 申论里最大的分值块，现在只有通用评分 | 中等偏大，动评分内核 | 建议先完成 P0 校准 |
| **P1** | 批改结果导出 Word / PDF | 求职/毕设场景常要打印或交材料 | 小（现有 markdown → docx 有现成路径） | 无 |
| **P2** | 老师档案页 Markdown 渲染 | 观感问题，老师讲义里的表格现在是一串字符 | 小 | 无 |
| **P2** | 考场模式严格化（禁换题 / 禁看答案入口） | 让模拟更接近真实考场 | 小 | 需你拍板策略 |
| **P2** | 成本样本扩大（跑 10~20 次不同题型） | 现在只有 1~2 次实测，成本曲线是估算 | 小（脚本已就绪 `.tools/e2e-real.mjs`） | 会花真钱（约 ¥1 以内） |
| **P3** | 上线（部署 + 限流 + 熔断） | 只有真要做成在线服务才需要 | 较大 | 见 `上线部署分析.md` |

## 五、未来要添加的功能

### 5.1 近期可做（都在现有架构内，不需要重写）

1. **更多省份题库**：山东 / 广东 / 江苏…… 管线已通用
   （`exams_config.py` 加省配置 → 提取 → 编入 → 汇编自动出目录），瓶颈是**逐卷人工核对**
2. **题型专项训练**：按题型组卷（概括归纳 / 综合分析 / 贯彻执行 / 提出对策 / 大作文），
   从现有 239 题里抽，不需要新内容
3. **作答对比**：同一道题的多次作答并排看（历史记录里已有数据，缺一个展示页）
4. **老师自定义**：让用户自建"老师"（自定侧重与权重）—— 现在的五位是硬编码的

### 5.2 中期（需要新的数据或模型能力）

1. **采分点自动建议（调模型那一档）**：现有 `--draft` 是启发式，升级成"模型读材料提候选 + 人工确认"
2. **作文智能点评**：从"扣点"走向"讲为什么"，需要更强的模型与更长的上下文预算
3. **跨记录趋势诊断**：把"连续三次栽在材料运用"这类模式挖出来（画像已有六维，缺时间轴分析）
4. **一键成册**：把若干次批改与复盘导成一份可打印的备考报告

### 5.3 明确不做（省得反复纠结）

- **OCR 识图 / 手写板**：投入产出比低，且与"本地优先、轻量分发"的定位冲突
- **通用作文批改**（不针对申论）：会稀释"申论专用"这个差异化点
- **云端账号体系**：本地优先是产品定位，不做强制登录

# 蓝笔申论 · 可复算与溯源手册

> **这份文档回答一个问题：屏幕上那个分数，凭什么可以信、怎么复算出来。**
> 面向答辩与面试，也面向"三个月后翻回一份旧记录、想知道当时发生了什么"的自己。
>
> 对应版本：**v0.25.0**｜相关代码：`frontend/src/agents/orchestrator.js`、`utils/grading/`、`utils/record.js`

---

## 〇、一句话答案

分数不是模型一句话报出来的，而是**五层流水线**的产物：能确定性算的部分全部交给代码，
只有"理解作答、判断是否命中采分点"这一步交给模型；**每一次批改的参数（标准版本、提示词版本、
模型、各老师温度）都随记录一起冻结存档**，结果页可直接展开查看。

---

## 一、一个分数是怎么来的（五层）

| 层 | 谁负责 | 产物 | 可复算性 |
|---|---|---|---|
| ① 题目标准层 | 预解析 / 人工精校，固定复用 | 采分点（分值 · 材料依据 · 判据关键词 · 同义词 / 反向要点） | **完全可复算**（数据固定） |
| ② 模型阅卷层 | 五位老师各自独立，互不看见对方分数 | 分数 + 逐句批注 + 采分点命中 + 六维画像 | 可复算到**分布**（受温度影响，见 §五） |
| ③ 纯代码校验层 | `utils/grading/rules.js`，零依赖 | 字数 / 段落 / 结构 / 照抄材料的客观扣分 | **完全可复算**（纯函数） |
| ④ 合议层 | 分歧检测 → 辩论 → 加权合议 | 最终分 + 圆桌说明 + 可信度 | 可复算（阈值与权重是固定常量） |
| ⑤ 训练层 | — | — | **未实现**（规划中） |

三条硬约束（都在代码里，不是约定）：

- **客观扣分封顶满分的 20%**（`DEDUCTION_CAP_RATIO = 0.2`），且**只作旁证、不改写 AI 分数** ——
  规则层不能一票否决模型的判断，只负责把板上钉钉的事实摆出来。
- **分歧阈值固定 15%**（`DISPUTE_THRESHOLD = 0.15`）：老师间得分率极差超过它才触发辩论，
  不是每轮都辩 —— 避免"演一场必然达成一致的圆桌"。
- **最终分在 `orchestrator.finish()` 里钳制**（`scoreGuard.js`），存档读入时再 sanitize 一次 ——
  模型的输出永不直接采信。

## 二、一次批改的时间线

```
点「开始批改」
  └─ ① 取标准：getStandard(questionId) → 有则用，没有则走「无标准裸判」（不报错、不罢工）
  └─ ② 裁材料：materialTrim 按题裁掉用不到的资料（解析不出资料号 / 大作文 / 引用缺失时不裁）
  └─ ③ 并行阅卷：每位老师独立拿到 paper，各自 temperature 见 §四
  └─ ④ 分歧检测：极差 > 15% → 仅真分歧才进辩论 → 加权合议
  └─ ⑤ 纯代码校验：字数 / 段落 / 结构 / 重复照抄
  └─ ⑥ 可信度评估：六信号汇总，天花板 96 分
  └─ ⑦ 冻结 provenance + 存档（IndexedDB 与 docs/practice/ 双写）
```

## 三、每份记录存了什么

一次批改落成的记录包含（节选关键项，完整见 `utils/record.js`）：

| 字段 | 内容 | 为什么必须存 |
|---|---|---|
| `final` | 最终分、等级、圆桌说明、建议 | 结论本身 |
| `results[]` | 每位老师的分数、批注、维度、扣分、改写 | **分歧是可复算的证据**，只存最终分就无从核对 |
| `debate` | 辩论过程（触发时才非空） | 说明分歧是怎么收敛的 |
| `hardRules` | 客观校验明细 + 是否触发封顶 | 第③层产物，纯代码可验 |
| `credibility` | 六信号 + 每项的 basis | 三年后翻回 md，还知道"这分有多少依据" |
| `provenance` | **标准版本 / 提示词版本 / 模型 / 各老师温度 / 深度开关 / 评分来源 / 冻结时间** | 复算的锚点 |
| `keyPoints` | 采分点命中情况 | 第①层与第②层的对账凭据 |

**存到哪**：本地 IndexedDB 必写；后端连得上就**同时**落到 `docs/practice/`（md + json 各一份），
可跨浏览器、能直接用编辑器翻。

## 四、结果页哪里看溯源

分数下方那行「**批改依据**」是可展开的，展开后逐条列出：

```
评分标准        人工校准标准 · v1.0 · 6 个采分点   （或：无标准（裸判））
提示词版本      grading-v1
模型            <调用时记录的模型名>
阅卷老师（温度） 袁东 0.1、周泰然 0.15、白鹭 0.3
评分来源        单人直采 / 加权合议 / 分歧复核后合议
深度模式        开（注入讲义原文）/ 关
冻结时间        2026/9/24 20:38:48
```

温度不是随手填的：**越依赖客观规则越低、越依赖综合判断越高**（袁东 0.1 → Kiwi 0.4）。
把它露出来，是因为它直接决定了复算时能期望多高的稳定性。

## 五、怎么复算（以及诚实的边界）

### 5.1 参数级复算（随时可做）

拿存档 json 的 `provenance` 字段，按同一组参数重跑。可预期：

- ✅ **必然一致**：采分点命中判断、客观校验结论、字数与段落统计 —— 这些是确定性计算
- ✅ **必然一致**：可信度六信号里"与程序粗判吻合度""阅卷完成度"这类由代码算出的项
- ⚠️ **会小幅浮动**：老师给的分、批注的措辞 —— 温度为 0.1~0.4，采样本身有随机性

**这是模型的性质，不是记录丢了什么。** 项目没有、也不会承诺"同输入必得同分数"，
能承诺的是：**同输入必得同一套判据与同一个量级的结论**。

### 5.2 人工复盘（不需要重跑）

`docs/practice/*.md` 里的记录已经带上可信度、采分点对照与圆桌说明，直接翻就能回答
"当时为什么给这个分"。这也是把 credibility 与 provenance 一起存档的原因 —— 只存一个数字，
三个月后它就是个孤儿。

### 5.3 降低随机性的办法

用**单人模式**（少一个采样源）、或**多位老师取合议**（互相抵消极端值）。
分歧被触发并复核过的记录，可信度里会体现为正向信号。

## 六、影响分数的因素（变更清单）

改这些，分数会跟着变 —— 复算前先确认它们是否与当时一致：

| 因素 | 存进 provenance | 说明 |
|---|---|---|
| 采分点标准及其版本 | ✅ source + version + points | 没有标准时走裸判，可信度**一律封顶「基本可信」**（84 分） |
| 提示词版本 | ✅ promptVersion | 改 `agents/skills.js` 的版本号即视为新的一版 |
| 模型 | ✅ model | 换模型 = 换了阅卷人 |
| 老师组合与温度 | ✅ temperatures | 组合不同，权重与合议结果就不同 |
| 深度模式 | ✅ deep | 开则注入讲义原文，判据更细、成本更高 |
| 材料裁剪 | ❌ | 由题干与材料内容确定性推导，同题同结果 |
| 作答正文 | ❌（记录里有） | 改一个字，命中的采分点就可能变 |

## 七、当前的真实缺口（不粉饰）

写这份文档时实测到的现状，答辩被问到时应当正面回答：

1. **采分点标准覆盖率极低**：随包分发的标准**实际只有 1 条人工精校样板**
   （`builtin-q-01`，v1.0，6 个采分点），其余题目全部走「无标准裸判」。
   所以结果页常看到"无标准（裸判）"，可信度被封顶在「基本可信」——**这是设计如此，
   不是 bug**：没有标准就承认没依据，老师一致不等于判得对。
   补齐它属于阶段二 D1（人工校准试点），需要人工专业判断，不是代码能代劳的。
2. **还没用真实 Key 跑过一次端到端**：链路与成本都在假 LLM 下验穿过，
   内容质量与真实成本没测过。
3. **可信度天花板 96 而非 100**：刻意留的余量 —— AI 批改不该给出"满分确定"的暗示。
4. **训练层（第⑤层）未实现**：闭环目前止步于"批改 → 复盘 → 下次推题"。

## 八、答辩 / 面试怎么用

- 被问「**AI 打分凭什么可信**」→ §一五层表 + §六变更清单：能确定算的不交给模型，
  交给模型的部分把参数冻结存档。
- 被问「**怎么保证可重复**」→ §五：说清"必然一致的部分"与"会浮动的部分"，
  并主动指出温度是浮动来源 —— 承认边界比承诺 100% 可复算更可信。
- 被问「**还差什么**」→ §七：覆盖率、真 Key 实测、训练层，三项都说得出口，
  且都写进了规划。

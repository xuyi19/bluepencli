# 界面改造可行性分析

> 评估对象：把界面改成「晟安申论式布局」+「Natural Organic 自然有机风格」
> 评估日期：2026-09-11
> 结论：**可行，但必须拆成两步做**；且动手前有一件事必须先办

---

## 一、结论先行

| 问题 | 结论 |

| 方向对不对？ | **对。** 自然有机风比新拟态更适合公考学习工具 |

## 二、那张截图里其实装了两件事

参考图里同时呈现了**布局**和**风格**，但这两件事的技术性质完全不同：

| | 布局改造 | 风格换肤 |
|---|---|---|
| 内容 | 顶部导航 → 左侧分组侧边栏；单列 → 多栏；文本框 → 方格答题纸 | 新拟态 → 自然有机 |
| 与另一件事的关系 | **完全解耦**，可以单独做 | 完全解耦，可以单独做 |
| 风险 | 低（结构改动，行为不变） | 高（约 290 处调用点，全局视觉） |
| 用户感知 | **强**（一眼看出变化，且方格纸是功能升级） | 强，但需要先习惯 |
| 建议顺序 | **第一步** | 第二步 |

**关键判断**：你看到截图觉得"这样更好"，其实**吸引力主要来自布局那一半**——左侧分组导航、材料与题目并排、底部方格作答纸。这些跟用什么配色无关。

方格答题纸尤其值得单独说：它不只是好看看，而是**让练习接近真实考场形态**。申论就是写在方格纸上的，现在是个 18 行的普通文本框。这个改动本身就有独立价值。

分项：主色 `#6d5dfc` 约 89 处、底色 `#e0e5ec` 约 42 处、拟态工具类 `neu-*` 约 161 处、自定义阴影 `shadow-[...]` 7 处。

前端总计约 3050 行代码。

### 3.2 意外发现一：token 层是空的

`frontend/tailwind.config.js` 里**已经定义了**风格 token：

```js
colors: {
  soft: '#e0e5ec',
  shadowDark: '#b8bcc2',
  shadowLight: '#ffffff',
  accent: '#6d5dfc',
}
```

但代码里 `bg-soft`、`text-accent` 的使用次数是 **0**。

也就是说：**token 层建好了却没人用，所有地方都在写硬编码色值。**

- 坏消息：换肤时没有"改一处生效全局"的捷径，290 处要逐处处理
- **好消息：这是一个一次性的补课机会。** 先把硬编码收敛进 token，之后再换风格（或以后想再换）只需要改配置文件

### 3.3 意外发现二：Arco Design 是个 400KB 的负担

全项目对 Arco 的使用只有两处：

```
views/ArticlesView.vue:  import { Message } from '@arco-design/web-vue'
views/PracticeView.vue:  import { Message } from '@arco-design/web-vue'
```

**没有使用任何一个 Arco 组件**（无 `<a-xxx>` 标签），却完整引入了 `arco.css`。

用体积对照可以证明这个依赖有多不划算：

| 项目 | 原始 | gzip |
|---|---|---|
| `@arco-design/web-vue/dist/arco.css` | 460 KB | 52.2 KB |
| 打包产物 CSS（实际发布的东西） | 405 KB | 52.3 KB |

**两者 gzip 后只差 77 字节** —— 也就是说，最终发布的样式文件几乎 100% 是 Arco，Tailwind 实际用到的部分被 purge 后小到可以忽略。

其他数据：`node_modules/@arco-design` 占 73 MB；单文件版产物共 3.4 MB，样式部分占约 12%。

> **顺手红利**：换肤时正好可以把这个依赖摘掉，用一个几十行的自定义轻提示替代。既减重又少一套样式来源。`style.css` 顶部那 12 行 `--primary-*` 主题变量覆盖也能一并清掉。

## 四、风格替换：逐条冲突清单

| 维度 | 当前（新拟态） | Natural Organic 要求 | 冲突级别 |
|---|---|---|---|
| **底色** | `#e0e5ec` 冷灰蓝 | `#faf6f1` 暖米色 | 需替换 |
| **主色** | `#6d5dfc` 紫蓝 | 禁用紫/蓝作主色；用 `#5c4033` 棕 + `#8b9d77` 鼠尾草 | **硬违规**（规范明令禁止项） |
| **阴影** | 拟态的**核心手段**，双向阴影做凸起/凹陷 | 禁 `shadow-lg` 及以上，最高 `shadow-md`；要"纸张质感" | **哲学冲突** |
| **圆角** | `rounded-xl` / `rounded-2xl` 规则圆 | `rounded-[2rem]` 或 blob 不规则形 | 需批量替换 |
| **字体** | 系统无衬线 | 标题 `font-serif` | 需引入衬线字体栈 |
| **动效** | `transition-*` 200-300ms | `duration-500+`、`ease-in-out`、hover 微下沉 | 需调整 |
| **老师色标** | 蓝/深绿/酒红/紫/棕 | 禁止冷色调（蓝紫除非辅助） | **需重新设计**（见下） |

### 为什么说阴影是"哲学冲突"而不是"参数调整"

新拟态的视觉全部建立在阴影上——`style.css` 里 4 个工具类 `.neu` / `.neu-sm` / `.neu-inset` / `.neu-press` 就是它的全部语言：

```css
.neu        { box-shadow: 6px 6px 12px #b8bcc2, -6px -6px 12px #ffffff; }
.neu-inset  { box-shadow: inset 3px 3px 6px #b8bcc2, inset -3px -3px 6px #ffffff; }
```

整个界面靠"凸起 / 凹陷"表达层级和状态。而自然有机风要求**几乎没有阴影**，改用纸张纹理和扁平色块表达层级。

这意味着：**161 处 `neu-*` 调用点在换肤后全部失效**，每一个都要换成"边框 + 底色 + 纹理"的新表达。这是本次改造最大的工作量所在，也是不能和布局改造混着做的原因——改成一半会得到一个既不像新拟态、也不像自然有机的中间态。

## 五、规范自身有两处矛盾（需要你拍板）

设计规范里有两个地方自相冲突，落地时必须人为决定：

### 5.1 "禁止完美圆形" vs "输入框必须 rounded-full"

- 「绝对禁止」章节写：**禁止使用完美的圆形/矩形**
- 「必须包含」章节写：输入框必须 `px-5 py-3 bg-white border border-stone-200 **rounded-full**`

`rounded-full` 就是标准胶囊形（两端完美半圆）。这两条不能同时满足。

**建议**：以「必须包含」的 token 模板为准（那是可直接复制的正确示例），把"禁止完美圆形"理解为"不要用几何正圆/正方形做装饰元素"，而不是约束输入框。

### 5.2 "禁止冷色调" vs 五位老师需要五种可区分的色标

当前老师色标：

| 老师 | 当前色 | 色相 |
|---|---|---|
| 袁东 | `#185fa5` | 蓝 ← 冷色 |
| 周泰然 | `#0f6e56` | 深绿 |
| 白鹭 | `#993556` | 酒红 |
| Kiwi | `#6d5dfc` | 紫 ← 冷色（且正是主色） |
| 李崇立 | `#854f0b` | 棕 |

色标是**功能性颜色**：五位老师在同一段作答上叠加批注，颜色必须能一眼分开。而自然有机风的色域（棕 / 赭 / 橄榄 / 鼠尾草 / 米黄）本身色相跨度窄，要凑出 5 个互相可分、且对比度达标的颜色有难度。

**两个选项**：

- **A. 严格守规范**：在棕色系里精细调，区分度会下降（尤其棕 vs 赭 vs 陶土），需要实测。色觉障碍用户可能更难分辨。
- **B. 色标作例外**（推荐）：规范原文是"禁止冷色调（蓝、紫**除非作为辅助**）"。色标属于功能性辅助色，可保留 1-2 个冷色以保证 5 色可区分，其余用大地色。这样既守住风格基调，又保住功能。

> 这个决定会直接影响 `agents/teachers.js`（5 处色值）和 `AnnotatedAnswer.vue` 的色标渲染逻辑（含重叠合并时的渐变分段）。改完必须重跑端到端验证看色标是否还分得开。

## 六、还有一笔约定代价

项目记忆里有明确约定：

> UI 风格：新拟态（`#e0e5ec` 底 + 双阴影），主色 `#6d5dfc`，顶部三栏 header。
> **样式与 resumatch-ai 统一。**

`E:\code\resumatch-ai`（简历匹配工具）与蓝笔申论构成"求职 + 考公"双作品矩阵，共用一套工程风格。

改成自然有机风之后，**两个项目的视觉统一性会断开**：

- 如果这是有意为之（两个产品各走各的性格）→ 没问题，甚至是加分项
- 如果你希望面试时掏出两个视觉同源的项目 → 需要想清楚，或者 resumatch-ai 也一起改

**这属于产品决策，不是技术问题，需要你定。**

## 七、风险清单

| 风险 | 级别 | 说明 |
|---|---|---|
| **无版本控制** | 🔴 高 | 项目不是 git 仓库。要动 ~290 处调用点，改坏了无法回滚。**必须先 `git init` 或做完整备份** |
| 中间态难看 | 🟠 中 | 换肤做到一半会既不像新拟态也不像自然有机。必须一次性做完一个完整页面再进入下一个 |

## 八、建议方案：拆两步

### 第一步：布局改造（建议先做）

**做什么**

1. `App.vue` 重写：顶部横向导航 → 左侧固定侧边栏，导航按语义分组
   - 可参考截图分组：开始 / 学习内容 / 实战练习 / 复盘统计 / 设置
   - 移屏端折叠为抽屉或顶部条
2. 练习页重排：材料区 + 题目区并排，作答区独立
3. **新增方格作答纸组件**（这步的重点）
   - 技术路线：CSS `repeating-linear-gradient` 画格线，等宽中文字体对齐字位
   - 需要处理：字数统计按格计、粘贴长文本、移动端降级为普通输入
4. 其余页面适配新容器宽度

**为什么先做**

- 与风格完全解耦，做完就能用，不会出现中间态
- 用户感知最强 —— 你从截图上想获得的东西，大部分在这一步
- 风险低，出错也只影响结构，不影响数据
- 做完后所有页面容器结构稳定了，再换肤不用改两遍

### 第二步：风格换肤（建议纳入后续版本）

**做什么**

1. **先补 token 层**：把 ~290 处硬编码收敛到 `tailwind.config.js`
   - 这一步不改视觉，改完界面应该和之前**看起来一样**
   - 这是安全网：之后换风格只改配置，不碰组件
   - 收敛后可以一次性验证"是否所有地方都走 token 了"
2. 改 token 值指向自然有机色板（底色 / 主色 / 边框 / 文字）
3. **重写 `style.css` 的拟态工具类**：`.neu*` 系列 → 自然有机的"边框 + 底色 + 纹理"表达
4. 逐页替换 161 处 `neu-*` 调用点
5. 引入衬线字体栈，标题改 `font-serif`
6. 动效统一为 `duration-500` + `ease-in-out`，加 hover 下沉
7. 重选老师色标（取决于第五节 5.2 的决定）
8. **摘掉 Arco**，替换 `Message` 为轻量提示（省 405 KB CSS）
9. 补 `prefers-reduced-motion` 支持（规范要求，目前没有）

## 九、需要你拍板的三个决定

### 决定 1：先做布局，还是两件一起做？

- **A. 先布局后换肤**（推荐）：布局先上线，风格作为下一版。风险低，见效快
- **B. 两件一起做**：一次到位，但中间态时间长，出问题难定位

### 决定 2：与 resumatch-ai 的统一怎么办？

- **A. 接受断裂**：蓝笔申论独立走自然有机风，resumatch-ai 保持新拟态
- **B. 一起改**：resumatch-ai 也换成自然有机风（工作量翻倍）
- **C. 都不改**：维持现状

### 决定 3：老师色标守不守"禁冷色"？

- **A. 严格守**：全大地色系，区分度需实测
- **B. 色标作例外**（推荐）：允许 1-2 个冷色作为功能性辅助色
